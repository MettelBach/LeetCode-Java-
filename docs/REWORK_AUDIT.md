# Аудит перед переработкой (05.10.2026)

Запрос пользователя: «дизайн, логика, скудность функционала и неправильная его работа, склад, каталоги, интеграции — всё неправильно». Вход в настоящий Base заблокирован Cloudflare; работаем по знаниям о BaseLinker и аудиту кода. Статус: ⏳ не сделано, ✅ сделано.

## Склад / каталоги — баги
1. ✅ Продукты без catalog_id (демо, offers→inventory) невидимы в каталоге; CSV-импорт создаёт дубликаты.
2. ✅ offers→inventory пишет products.stock без product_stock → потеря остатков.
3. ⏳ Модалка варианта шлёт `stock` = сумма складов → раздувание (UI переписать на остатки по складам).
4. ✅ Родитель с вариантами принимает собственный остаток (stock.ts: stockIsDerived).
5. ✅ Заказ привязывается к родителю / другому каталогу (findProduct без родителей, с приоритетом каталога).
6. ⏳ parent_id не валидируется (сам себе, вариант варианта).
7. ⏳ Уникальность SKU в каталоге (смена каталога, bulk set_catalog, варианты) — + уникальный индекс в миграции ✅.
8. ⏳ FK-ошибки → 500 (удаление товара с документами, неизвестный склад/категория/каталог).
9. ✅ Отрицательные остатки не проверяются (теперь 409, кроме заказов и складов с allow_negative).
10. ⏳ Номера документов дублируются (COUNT+1 на черновике) → номер при подтверждении MAX(seq)+1.
11. ⏳ Черновик не редактируется; подтверждённый нельзя отменить; PZ перезаписывает цену закупа (нужна средняя — updateAverageCost ✅ в stock.ts).
12. ⏳ Удаление склада теряет остатки (сумма +5/−5); интеграции ссылаются на удалённый склад.
13. ⏳ CSV: экспорт без каталога, остаток=сумма, parent_id игнор, без SKU дубли, многострочные поля, польские заголовки, ошибки по строкам.
14. ⏳ Категории: фильтр без подкатегорий, плоский UI, нельзя сменить родителя, не привязаны к каталогу.
15. ⏳ Список по умолчанию «Все каталоги»; /products/search игнорирует каталог.
16. ✅ История остатков без пользователя и документа (doc_id, user_name добавлены).
17. ⏳ Объединение заказов с разных складов.

## Склад — чего нет (по приоритету)
Каталог как контейнер (языки, группы цен, склады, интеграции, умолчания) · группы цен · резервирование · карточка товара с вкладками (Информация, Тексты по языку×каналу, Фото ≤16, Параметры, Цены, Остатки, Варианты+генератор, Комплект, Доп. поля, Оферты, История) · список: дерево категорий, раскрытие вариантов, выбор колонок, inline-редактирование, фильтры · импорт с маппингом колонок · комплекты · инвентаризация · документы BO/ZW/INW, дата, PDF · внешние склады · теги, лог изменений.

## Заказы — баги
1. ⏳ Merge: [A,A] кладёт A в корзину, удваивает оплату, теряет доставку; merge заказов из корзины.
2. ⏳ Заказ из корзины снова списывает склад при смене статуса.
3. ⏳ stock_deduct=status:X сломан (создание сразу в X, отмена→X, корзина→восстановление, on_create + сразу «Отменён»). → одна функция reconcileStock + stock_action у статуса.
4. ⏳ Возвраты: количество больше заказанного, повторные, на отменённый заказ, чужой product_id, возврат денег > оплаты.
5. ⏳ Корректировки считаются от исходной фактуры, а не от последнего состояния.
6. ⏳ Нумерация фактур не по датам, задним числом, невалидные даты, чек+фактура дважды, UTC вместо Europe/Warsaw, нет курса NBP.
7. ⏳ ФЕЙКОВЫЕ НОМЕРА ОТПРАВЛЕНИЙ уходят на маркетплейс (createShipment генерирует номер; send_tracking отправляет). Отправки для отменённых/без адреса.
8. ⏳ Оплаты: мусорная дата, нет даты при создании, sync меняет paid_amount без события order_paid.
9. ⏳ 500 вместо 400 (несуществующий product_id, status_id, note к несуществующему заказу, move_to статус).
10. ⏳ Ссылка «страница заказа» в карточке без account id → 404.
11. ⏳ LIKE без экранирования (% и _), невалидные фильтры молча, отрицательная сумма заказа, CSV.
12. ⏳ Split целыми строками, оплата остаётся на исходном; duplicate копирует auction_id.
13. ⏳ Автоматизация читает текущее состояние, а не toStatusId; потеря depth/ruleIds.
14. ⏳ Нет блокировки после фактуры; date_add «2099-99-99».
